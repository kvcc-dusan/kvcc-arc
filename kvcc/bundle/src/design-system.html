kvcc design system

Arc-based tokens, rules and components. Everything below renders from the real token file, so change the theme or accent and the whole page follows.

Apply this system

Instructions for anyone, human or model, designing a screen with kvcc. The exact token values are printed below as text, so copy them instead of approximating.

  1. 1. Paste the token CSS as isIncluding the last block, which maps --font-display and --font-body to the plain family names Geist and Inter. Load both from Google Fonts (400 and 500) under those names, or the text falls back to the system font. Use the variable names and values from the token reference below. Do not invent your own variables or pick colors by eye. Every color, radius, space, shadow and font comes from a token.
  2. 2. Sizes from tokens, not literalsHeights are --control-height-sm (36px), --control-height-md (44px, the default) and --control-height-lg (50px). Gaps and padding are --space-N. Radii are --radius-control, --radius-panel, --radius-surface, --radius-pill. Never write 44px, 12px or 26px as a literal when a token exists.
  3. 3. Type only from the scaleSizes are 12, 14, 16, 18, 22, 28, 36, 52 and 72px (--text-xs to --text-5xl). Body text is 14 or 16px, never 15 or 13. Weights 400 and 500 only. Geist for headings of 30px and up, Inter for everything else.
  4. 4. Primary buttonBackground --foreground, text --background, radius --radius-control (18px), height 44px, weight 500. Secondary: --surface with a 1px --border. Ghost: transparent, --text-secondary. One primary per screen, and it is the main action (Save changes, not Discard). The accent is not a button fill.
  5. 5. FieldsVisible label above, 44px tall, 18px radius, 1px --border-strong, background --surface. Focus is the border going to --foreground.
  6. 6. Switch and checkboxUse --control-on for the on track, --control-track for off, --control-thumb and --control-thumb-on for the thumb, --control-glyph for a check. Track 42 by 24px, thumb 18px. Never --accent for these.
  7. 7. SurfacesPanels are --surface with a 1px --border and --radius-panel (26px), no shadow. Shadow (--shadow-floating) only on floating layers: menus, dialogs, a sticky save bar.
  8. 8. AccentUse --accent for the active nav item, selected rows, links and small cues only. Active nav item: --accent-subtle background with --accent-strong text.
  9. 9. Keyboard and motionVisible focus on every control using the shared outline in the token CSS. Every transition has a prefers-reduced-motion branch. State changes (switch, drawer) never overshoot.
  10. 10. CopySentence case, no em dashes, verb plus object on buttons, label sample data as sample data.
  11. 11. PhonesControls 44px tall, 16px gutters, one column, no sideways scroll. Navigation is a drawer or a bottom bar with 44px targets.
  12. 12. Menus and popoversContainer --surface-raised, 1px --border, --radius-panel (26px), padding --space-1, --shadow-floating. Items are --control-height-sm (36px) tall with radius calc(var(--radius-panel) - 6px); hover and keyboard highlight use --surface-muted. A destructive item has --danger text and a faint danger tint highlight. Arrow keys move between items, Enter picks, Escape closes and returns focus to the trigger, Tab closes.
  13. 13. ChartsColors only from --series-1 to --series-4, never the accent as decoration. Gridlines --border, baseline --border-strong, the average as a 1px dashed --text-secondary line with an "Avg N" label. Axis text --text-xs in --text-muted with tabular numerals. Bars have a 4px rounded top. The value of a bar is readable by hover, focus or arrow keys, not only in a tooltip attribute.
  14. 14. TablesHeader cells --text-sm in --text-muted, weight 500. Rows at least --control-height-lg tall, divided by 1px --border-subtle. Numbers right-aligned with tabular numerals. Status is a pill with a dot in --success, --warning or --danger and always a text label. A selected row uses --accent-subtle. Sortable headers are buttons with aria-sort.
  15. 15. Stat cardsLabel --text-sm in --text-secondary, value in Geist --text-3xl with tabular numerals, then a change line with an arrow and text. Color the change --success only when the change is good and --danger only when it is bad. An up arrow on overdue tasks is bad, so the direction of the arrow never decides the color.
  16. 16. Destructive actionsNever delete on the first click. Open a dialog that names the object and the consequence ("Delete Partner portal? Its 19 open tasks are removed for everyone.") with a secondary Cancel and a danger button that repeats the verb and object.

Rules that carry the look

Most of the visual language is a handful of constraints. Hold these and almost any layout reads as the same system.

  • Semantic color roles onlyNever raw hex or the neutral ramp in product code. One accent per screen, mostly neutral.
  • Three radiiControls 18px, panels 26px, surfaces 34px. Nested radius is outer minus padding.
  • Geist at 30px and up, Inter belowWeights 400 and 500 only. Sentence case everywhere, no uppercase labels.
  • Borders over shadowsCards rest on a hairline. Shadow is for floating layers: menus, popovers, dialogs.
  • State never overshootsSwitches, drawers and progress settle without bounce. Springs for movement, color for press feedback on anchors.
  • One focus ringA shared outline for keyboard focus only. No hand-written rings. Honor reduced motion everywhere.
  • Copy is part of the systemVerb plus object on buttons, no em dashes, errors say how to fix it, sample data is labeled.
  • 4px grid16px inside a group, 24px between regions, 44px default control height.
